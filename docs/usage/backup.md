# 备份与恢复

备份是实例级的数据保护手段。主控提供「创建 / 恢复 / 删除」三类操作，是否可用取决于平台驱动。

## 入口

- 实例详情 → 备份；
- 或 `POST /api/client/backup/create/:hs_name/:vm_uuid`。

## 创建备份

| 字段 | 说明 |
|---|---|
| 备份名称 | 默认时间戳 |
| 类型 | 全量（当前实现以全量为主） |
| 存储位置 | 主机配置的 `backup_path` |
| 备注 | 可选 |

提交后生成异步任务，可在任务管理查看进度。

## 恢复

::: danger 覆盖风险
恢复会覆盖当前实例磁盘。执行前建议先对现状再做一次备份。
:::

恢复流程：

1. 选择备份文件；
2. 确认实例将关机；
3. 执行恢复任务；
4. 启动并验证。

## 删除

- 删除备份文件不可恢复；
- 有保留策略时，按策略自动清理；
- 删除失败通常是文件被占用或权限不足。

## 平台差异

| 平台 | 实现 |
|---|---|
| Proxmox | `vzdump` / `qmrestore` |
| QEMU | `qemu-img` 快照或磁盘复制 |
| ESXi | 快照导出（视驱动） |
| LXD | `lxc export` / `lxc import` |
| Docker | 镜像导出 / 数据卷打包 |
| Hyper-V | `Export-VM` / `Checkpoint` |
| VirtualBox | `VBoxManage export/import` |
| SmolVM | rootfs 复制 |
| MuMu | 不支持 |

「备份」与「快照」不是同一概念：快照通常依赖存储层且与磁盘链绑定，主控当前抽象的是备份文件。

## 保留策略建议

| 场景 | 建议 |
|---|---|
| 日更业务 | 每日一次，保留 7 天 |
| 周更业务 | 每周一次，保留 4 周 |
| 关键节点 | 变更前手动备份，长期保留 |

在宿主机侧配置清理脚本，避免备份盘被占满。

## 命令行

```bash
opidcs vm show <uuid> --output json | jq '.backups'
```

## 常见问题

| 现象 | 处理 |
|---|---|
| 创建失败 | 检查 `backup_path` 空间与权限 |
| 恢复后起不来 | 检查引导与磁盘顺序 |
| 备份文件很大 | 使用压缩 / 增量（平台支持时） |
| 任务卡住 | 查看平台侧进程与磁盘 IO |
