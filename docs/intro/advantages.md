# 核心优势

## 1. 单二进制主控，部署成本低

CloudHost 编译后是一个可执行文件（`hostagent`），不需要 Python、Node 或外部数据库服务：

- 数据默认落在 SQLite（`data/data.db`），也可切换 MySQL / PostgreSQL，开箱即用；
- 静态前端与 noVNC 页面随二进制一起分发；
- Linux 一条 `install.sh` 注册 systemd，Windows 一个 Inno 安装包注册服务。

这意味着你不需要为了「一个面板」维护一套运行时环境，也不会出现「升级 Python 依赖把面板升挂」的问题。

## 2. 平台差异被驱动层吸收

主控不假设所有平台都一样。每个平台有独立的驱动实现与能力元信息（`engine_config`），运行时决定：

- 哪些字段可以填（GPU、显存、带宽、ISO、数据盘）；
- 哪些操作不支持（暂停、USB 直通、快照式备份）；
- 哪些页签要锁住（PCI / USB / EFI / HDD）。

前端据此渲染表单与提示，而不是让用户在报错里猜。

## 3. 一套 API 同时服务控制台、CLI 与财务插件

`/api` 下的资源模型是唯一的：

- 浏览器控制台调用它；
- `opidcs` 命令行调用它；
- IDCSmart / SwapIDC 插件调用它；
- 你自己的自动化脚本也可以调用它。

新增能力只需要在主控实现一次，三端同时获得。

## 4. 网络能力是内建的，不是外挂脚本

- **NAT 端口转发**：按实例维护规则，支持批量下发与回收。
- **爱快联动**：DHCP 静态绑定与 ARP 绑定，IP 与 MAC 不再靠手记。
- **反向代理**：主控托管 Caddy 进程与 `Caddyfile`，为用户域名自动签发证书。
- **VNC / SSH**：主控侧内置 6080 与 7681 两个代理端口，用户无需直连宿主机。

## 5. 面向售卖，而不是只面向运维

实例归属、共享权限、访问密钥、配额重算、财务插件 —— 这些是「把资源卖出去」必需的东西，OpenIDCS 把它们做进核心模型，而不是留给你写脚本。

## 6. 可观测、可回滚

- 所有耗时操作走异步任务，可查询进度、可取消；
- 资源删除采用墓碑（tombstone）与对账（outbox）机制，失败可重试；
- 日志按级别同时写文件与数据库，支持按主机/实例检索；
- 升级只需替换二进制，数据目录独立保留。

## 7. 开源与可扩展

AGPLv3 协议，主控、前端、Agent、插件全部开源。你可以：

- 新增一个平台驱动（实现 `HostDriver` 接口）；
- 新增一种财务插件（调用主控 REST API）；
- 用 `opidcs` 的命令表扩展自己的运维命令。

## 与其他方案的取舍

| 维度 | OpenIDCS | 单平台面板（如 PVE 自带） | 通用云管平台 |
|---|---|---|---|
| 多平台纳管 | 10+ 平台同一模型 | 仅自家平台 | 通常支持，但重 |
| 部署成本 | 单二进制 + SQLite | 中 | 高（依赖多组件） |
| 售卖能力 | 内建财务插件 | 无 | 有，但需定制 |
| 二次开发 | Go + React，接口清晰 | 受限 | 视产品而定 |

> 如果你的场景只需要一种虚拟化平台、也不打算对外售卖，直接用平台自带面板会更省事；OpenIDCS 的价值在「多平台 + 售卖 + 统一 API」。
